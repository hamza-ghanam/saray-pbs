Dashboard API

Frontend visualization guide — what to render, how to render it, and for whom

Endpoint GET /api/dashboard/overview
Auth Authorization: Bearer {token}
Cache Response is cached 60 seconds per user + role + date range + project
Default Range Start of current month → now (if no from/to passed)

Endpoint & Parameters

Query Parameters

ParamTypeRequiredDescription
fromYYYY-MM-DDNoStart of the reporting window. Defaults to start of current month.
toYYYY-MM-DDNoEnd of the reporting window. Defaults to now. Must be ≥ from.
project_idintegerNoScope all metrics to a single building/project. Omit for all projects.
debug0 or 1NoAppends a debug key with the resolved params. Only works for users with dashboard.debug permission.
Date range tip: Always pass both from and to when the user changes the date picker, so the server doesn't fall back to defaults silently. Show the resolved range from data.meta.range in the UI to confirm what period is displayed.

Role Visibility

The data.meta.role field tells you the current user's role. Use it to show or hide sections:

SectionVisible toNotes
kpis All roles Always present. Render for everyone.
breakdowns All roles Always present. Render for everyone.
alerts CEO CSO COO CRM Officer System Maintenance Array will be [] for other roles — simply hide the section when empty.
queues.approvals.bookings CEO CSO COO CRM Officer System Maintenance CEO sees only bookings missing CEO approval. CSO sees only bookings missing CSO approval. COO/CRM see all pipeline bookings.
tables CEO CSO COO CRM Officer System Maintenance Arrays will be [] for other roles.
Rule of thumb: check data.meta.role on page load and hide entire sections (not just their data) when the role doesn't apply — avoid showing empty cards or tables with "No data" for sections the user is never intended to see.

Section: meta

Informational only — use it to drive the UI, not display it directly.

FieldUse in UI
meta.range.from / meta.range.toShow the resolved date range in the header (e.g. "Jun 1 – Jun 9, 2026") so the user always sees what period the numbers represent.
meta.timezoneDisplay in a tooltip on the date range ("All times in Asia/Dubai"). Useful for teams across time zones.
meta.roleDrive role-based section visibility. Store in component state — don't re-fetch just for this.
meta.project_idReflect the active project filter in the UI. null = all projects.

Section: alerts

Role-gated: CEO · CSO · COO · CRM Officer · System Maintenance only. Hide this section entirely when alerts is [].

Render as a horizontal strip of dismissible banners at the top of the page, one per alert. Each alert has a type and a count.

typeVisualizationCopy suggestionColor
stuck_bookings ⚠ Alert Banner "{count} booking{s} stuck in pipeline for more than {threshold_hours}h" Amber / warning
overdue_installments ⚠ Alert Banner "{count} installment{s} overdue — action required" Red / danger
installments_pending_verification ℹ Alert Banner "{count} payment{s} awaiting verification" Blue / info
Each banner should link to the relevant management page — e.g. stuck_bookings → booking pipeline, overdue_installments → GET /api/installments?status=overdue.

Section: breakdowns

breakdowns.units_by_status Donut Chart

Array of { status, count }. Render as a donut chart. Each slice = one unit status.

status valueSuggested color
AvailableGreen #1a7f37
HoldAmber #d97706
Pre-HoldLight Amber
BookedBlue #2E5299
CompletedPurple #7c3aed
PendingGray
Show the total unit count in the donut center. On hover/click of a slice, show the status name + count + percentage of total.

breakdowns.bookings_by_status Vertical Bar Chart

Array of { status, count }. Render as a vertical bar chart. X-axis = booking status, Y-axis = count. The status order in the response follows the pipeline progression: Pre-Booked → RF Pending → SPA Pending → Booked → Completed → Cancelled.

status valueMeaningSuggested color
Pre-BookedEarly pipeline stageSky blue
RF PendingReservation form awaiting signatureBlue
SPA PendingSales & Purchase Agreement pendingPurple
BookedFully bookedGreen
CompletedDeal closedDark green
CancelledCancelledRed

breakdowns.top_projects_by_booking_value_mtd Horizontal Bar Chart

Array of up to 5 projects, sorted by total_value descending. Each item: project.name, total_value, bookings_count.

Render as a horizontal bar chart — project name on the Y-axis, bar width = total_value. Show both the formatted currency value and booking count as bar labels.

If project_id is set in the filter, this chart will show only that project (1 bar). Consider hiding it or replacing it with a single project summary card in that case.

Section: queues.approvals.bookings

Role-gated: CEO · CSO · COO · CRM Officer · System Maintenance. The array is [] for other roles — hide the section.

Up to 15 bookings needing an approval action. Render as a compact data table with an action button on each row.

FieldColumn labelHow to render
idBooking #Link to booking detail page
statusStatusColored badge (see booking status colors above)
total_valueValueFormatted currency (AED)
created_atCreatedRelative time ("3 days ago") + full date tooltip
unit_idUnitLink to unit detail (fetch unit_no separately if needed)
—Action"Review" button → navigate to booking detail page
CEO vs CSO behavior: The server already filters the queue by role — CEO sees only bookings missing CEO approval, CSO sees only bookings missing CSO approval. No additional frontend filtering needed.
