5 · List All Installments

GET /api/installments Admin-wide paginated list

Returns a paginated list of all installments across all bookings. Soft-deleted bookings are excluded. Results are ordered by due date ascending.

view installments

Query Parameters

ParameterTypeRequiredDescription
periodstringNoShorthand date window: today, this_week, this_month. Ignored if due_from / due_to are set.
due_fromYYYY-MM-DDNoDue date on or after this date. Takes precedence over period.
due_toYYYY-MM-DDNoDue date on or before this date. Must be ≥ due_from.
statusstringNopending, partially_paid, paid, overdue, waived
pending_verificationbooleanNoWhen true, returns only installments with at least one payment awaiting verification.
booking_idintegerNoFilter by a specific booking.
project_idintegerNoFilter by building / project ID.
per_pageintegerNoItems per page. Default: 25. Max: 100.

8 · Record a Payment

POST /api/bookings/{booking_id}/installments/{installment_id}/payments

Records a new payment against an installment. The payment is created with status pending_verification and must be verified before it affects paid_amount.

record installment payment

Path Parameters

ParameterTypeDescription
booking_idintegerThe booking ID.
installment_idintegerThe installment ID.

Request Body — multipart/form-data

FieldTypeRequiredDescription
amountnumberRequiredPayment amount. Must be > 0.
payment_datedateRequiredDate the payment was made. Format: YYYY-MM-DD.
payment_methodstringOptionalcash, bank_transfer, cheque, card, other
reference_numberstringOptionalTransaction / cheque reference. Max 255 chars.
receiptfileOptionalAccepted: pdf, jpg, jpeg, png. Max 5 MB.
notesstringOptionalFree-text notes.
Note: Even if the amount fully covers the installment, status will not change to paid until the payment is verified.

Success Response — 201 Created

{
  "message": "Payment recorded successfully.",
  "payment": {
    "id": 302,
    "installment_id": 5208,
    "amount": "9569.90",
    "payment_date": "2026-06-09",
    "payment_method": "cheque",
    "reference_number": "CHQ-002",
    "status": "pending_verification",
    "verified_at": null,
    "notes": null,
    "created_at": "2026-06-09T07:15:00.000000Z",
    "created_by": { "id": 3, "name": "Agent Name" }
  },
  "installment": {
    "id": 5208,
    "status": "partially_paid",
    "paid_amount": "5000.00",
    "remaining_amount": 9569.90
  }
}

Error Responses

StatusCondition
403User lacks permission
404Installment does not belong to this booking
422Validation error, or business rule violation (e.g. installment already paid or waived)
500Server error (receipt upload or DB failure)

9 · Verify a Payment

POST /api/bookings/{booking_id}/installments/{installment_id}/payments/{payment_id}/verify

Marks a payment as verified. Updates the installment's paid_amount and recalculates its status. No request body needed.

verify installment payment

Path Parameters

ParameterTypeDescription
booking_idintegerThe booking ID.
installment_idintegerThe installment ID.
payment_idintegerThe payment ID to verify.

Success Response — 200 OK

{
  "message": "Payment verified successfully.",
  "payment": {
    "id": 302,
    "status": "verified",
    "verified_at": "2026-06-09T09:00:00.000000Z",
    "verified_by": { "id": 5, "name": "Admin User" }
  },
  "installment": {
    "id": 5208,
    "status": "paid",
    "paid_amount": "14569.90",
    "remaining_amount": 0
  }

Error Responses

StatusCondition
403User lacks permission
404Payment does not belong to this installment/booking
422Payment is not in pending_verification status
500Server error

10 · Reject a Payment

POST /api/bookings/{booking_id}/installments/{installment_id}/payments/{payment_id}/reject

Marks a payment as rejected. The installment's paid_amount is not affected. The rejection reason is stored in rejection_reason — separate from the payment's notes.

reject installment payment

Path Parameters

ParameterTypeDescription
booking_idintegerThe booking ID.
installment_idintegerThe installment ID.
payment_idintegerThe payment ID to reject.

Request Body — JSON

FieldTypeRequiredDescription
reasonstringOptionalRejection reason. Max 1000 chars. Stored in rejection_reason.

Success Response — 200 OK

{
  "message": "Payment rejected successfully.",
  "payment": {
    "id": 302,
    "status": "rejected",
    "rejection_reason": "Receipt is unclear.",
    "verified_at": null
  }
}

Error Responses

StatusCondition
403User lacks permission
404Payment does not belong to this installment/booking
422Payment is already verified or rejected
500Server error

Generates and stores a PDF invoice for a verified payment. Payment must be in verified status.

issue invoice

ParameterTypeDescription

Request Body — JSON

12 · Download Invoice PDF

GET /api/invoices/{invoice_id}/download Binary PDF response

Downloads the PDF file for an invoice. Response is a raw binary PDF — not JSON.

view invoices

Path Parameters

ParameterTypeDescription
invoice_idintegerThe invoice ID.

Success Response — 200 OK

Returns the PDF as a binary download:

HeaderValue
Content-Typeapplication/pdf
Content-Dispositionattachment; filename="INV-2026-0055.pdf"
With Axios set responseType: 'blob' and trigger a download via URL.createObjectURL(). In the browser you can also use a direct <a href="..."> or window.open(url).

Error Responses

StatusCondition
403User lacks permission
404Invoice not found, or PDF not yet generated

13 · Status Reference

Installment Statuses

ValueMeaning
pendingNo verified payment yet. Due date may be in the future.
partially_paidSome verified payments exist but do not fully cover the amount.
paidFully covered by verified payments.
overdueDue date has passed with no verified payment covering the balance.
waivedManually waived — no payment required.

Payment Statuses

ValueMeaning
pending_verificationPayment recorded, waiting for an authorized user to verify it.
verifiedPayment confirmed. Contributes to the installment's paid_amount.
rejectedPayment rejected (e.g. bad receipt). Does not contribute to paid_amount.
refundedPayment was refunded after verification.
