Installment Payment API

Base URL: http://localhost:8000/api

Authentication: All endpoints require a Bearer token via Sanctum.
Include the header: Authorization: Bearer {token}

Date format: All dates are returned and accepted as YYYY-MM-DD (e.g. 2026-06-09).

1. List All Installments

GET /api/installments

Returns a paginated list of all installments across all bookings. Soft-deleted bookings are excluded. Results are ordered by due date ascending.

Required Permission

view installments

Query Parameters

ParameterTypeRequiredDescription
periodstringNoShorthand date window. One of: today, this_week, this_month. Ignored if due_from or due_to are provided.
due_fromdate (YYYY-MM-DD)NoFilter installments with due date on or after this date. Takes precedence over period.
due_todate (YYYY-MM-DD)NoFilter installments with due date on or before this date. Must be ≥ due_from.
statusstringNoOne of: pending, partially_paid, paid, overdue, waived
pending_verificationbooleanNoWhen true, returns only installments that have at least one payment awaiting verification.
booking_idintegerNoFilter by a specific booking.
project_idintegerNoFilter by building/project ID.
per_pageintegerNoItems per page. Default: 25. Max: 100.

4. Record a Payment

POST /api/bookings/{booking_id}/installments/{installment_id}/payments

Records a new payment against an installment. The payment is created with status pending_verification and must be verified by an authorized user before it affects the installment's paid_amount.

Required Permission

record installment payment

Path Parameters

ParameterTypeDescription
booking_idintegerThe booking ID.
installment_idintegerThe installment ID.

Request Body

Use multipart/form-data (required when uploading a receipt file).

FieldTypeRequiredDescription
amountnumberRequiredPayment amount. Must be > 0.
payment_datedateRequiredDate the payment was made. Format: YYYY-MM-DD.
payment_methodstringOptionalOne of: cash, bank_transfer, cheque, card, other
reference_numberstringOptionalTransaction or cheque reference. Max 255 characters.
receiptfileOptionalPayment receipt. Accepted types: pdf, jpg, jpeg, png. Max size: 5 MB.
notesstringOptionalFree-text notes about this payment.
Note: Even if the payment amount fully covers the installment, the installment status will not change to paid until the payment is verified.

Success Response — 201 Created

{
  "message": "Payment recorded successfully.",
  "payment": {
    "id": 302,
    "installment_id": 5208,
    "amount": "9569.90",
    "payment_date": "2026-06-09",
    "payment_method": "cheque",
    "reference_number": "CHQ-002",
    "status": "pending_verification",
    "verified_at": null,
    "notes": null,
    "created_at": "2026-06-09T07:15:00.000000Z",
    "installment": { ... },
    "created_by": { "id": 3, "name": "Agent Name" }
  },
  "installment": {
    "id": 5208,
    "status": "partially_paid",
    "paid_amount": "5000.00",
    "remaining_amount": 9569.90
  }
}

Error Responses

StatusCondition
403User lacks permission
404Installment does not belong to this booking
422Validation error, or business rule violation (e.g. installment already fully paid or waived)
500Server error (receipt upload or DB failure)

5. Verify a Payment

POST /api/bookings/{booking_id}/installments/{installment_id}/payments/{payment_id}/verify

Marks a payment as verified. This updates the installment's paid_amount and recalculates its status (e.g. partially_paid → paid). No request body is needed.

Required Permission

verify installment payment

Path Parameters

ParameterTypeDescription
booking_idintegerThe booking ID.
installment_idintegerThe installment ID.
payment_idintegerThe payment ID to verify.

Request Body

None required.

Success Response — 200 OK

{
  "message": "Payment verified successfully.",
  "payment": {
    "id": 302,
    "status": "verified",
    "verified_at": "2026-06-09T09:00:00.000000Z",
    "verified_by": { "id": 5, "name": "Admin User" },
    "installment": { ... }
  },
  "installment": {
    "id": 5208,
    "status": "paid",
    "paid_amount": "14569.90",
    "remaining_amount": 0
  }
}

Error Responses

StatusCondition
403User lacks permission
404Payment does not belong to this installment/booking
422Business rule violation (e.g. payment is not in pending_verification status)
500Server error

6. Reject a Payment

POST /api/bookings/{booking_id}/installments/{installment_id}/payments/{payment_id}/reject

Marks a payment as rejected. The installment's paid_amount is not affected. The rejection reason is stored separately in rejection_reason and does not overwrite the payment's notes.

Required Permission

reject installment payment

Path Parameters

ParameterTypeDescription
booking_idintegerThe booking ID.
installment_idintegerThe installment ID.
payment_idintegerThe payment ID to reject.

Request Body — JSON

FieldTypeRequiredDescription
reasonstringOptionalReason for rejection. Max 1000 characters. Stored in rejection_reason.

Success Response — 200 OK

{
  "message": "Payment rejected successfully.",
  "payment": {
    "id": 302,
    "status": "rejected",
    "rejection_reason": "Receipt is unclear.",
    "verified_at": null
  }
}

Error Responses

StatusCondition
403User lacks permission
404Payment does not belong to this installment/booking
422Business rule violation (e.g. payment is already verified or rejected)
500Server error

7. Issue an Invoice

POST /api/bookings/{booking_id}/installments/{installment_id}/payments/{payment_id}/invoice

Generates and stores a PDF invoice for a verified payment. Can only be called on a payment that is already in verified status.

Required Permission

issue invoice

Path Parameters

ParameterTypeDescription
booking_idintegerThe booking ID.
installment_idintegerThe installment ID.
payment_idintegerThe verified payment to invoice.

Request Body — JSON

FieldTypeRequiredDescription
vat_ratenumberOptionalVAT percentage to apply. Default: 0. Range: 0–100.
notesstringOptionalNotes to print on the invoice.

Success Response — 201 Created

{
  "message": "Invoice issued successfully.",
  "invoice": {
    "id": 55,
    "invoice_number": "INV-2026-0055",
    "amount": "9569.90",
    "vat_rate": "5.00",
    "vat_amount": "478.50",
    "total_amount": "10048.40",
    "pdf_path": "invoices/INV-2026-0055.pdf",
    "notes": null,
    "created_at": "2026-06-09T09:05:00.000000Z"
  }
}

Error Responses

StatusCondition
403User lacks permission
404Payment not found or does not belong to this installment/booking
422Business rule violation (e.g. payment is not verified, or invoice already issued)
500Server error (PDF generation failure)

8. Download Invoice PDF

GET /api/invoices/{invoice_id}/download

Downloads the PDF file for an invoice. The response is the raw PDF binary (not JSON). The browser/client should treat it as a file download.

Required Permission

view invoices

Path Parameters

ParameterTypeDescription
invoice_idintegerThe invoice ID.

Success Response — 200 OK

Returns the PDF file as a binary download with:

  • Content-Type: application/pdf
  • Content-Disposition: attachment; filename="INV-2026-0055.pdf"

In the browser, use a direct <a href="..."> tag or window.open(url). With Axios, set responseType: 'blob' and trigger a download programmatically.

Error Responses

StatusCondition
403User lacks permission
404Invoice not found, or the PDF file has not been generated yet

9. Status Reference

Installment Statuses

ValueMeaning
pendingNo payment recorded yet. Due date may be in the future.
partially_paidSome verified payments exist but do not fully cover the amount.
paidFully covered by verified payments.
overdueDue date has passed and no verified payment covers the balance.
waivedManually waived — no payment required.

Payment Statuses

ValueMeaning
pending_verificationPayment recorded, waiting for an authorized user to verify it.
verifiedPayment confirmed. Contributes to the installment's paid_amount.
rejectedPayment rejected (e.g. bad receipt). Does not contribute to paid_amount.
refundedPayment was refunded.

Typical Payment Lifecycle

Record Payment  →  pending_verification
                         │
             ┌───────────┴───────────┐
           verify                 reject
             │                       │
          verified               rejected
             │
        issue invoice
             │
         (PDF ready to download)
