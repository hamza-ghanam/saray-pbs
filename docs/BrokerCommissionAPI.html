Broker Commission API

Complete frontend reference — rate management, commission listing & payment recording

Base URL http://localhost:8000/api
Authentication Authorization: Bearer {token} (Sanctum)
Date Format YYYY-MM-DD for dates, YYYY-MM-DD HH:MM:SS for datetimes

Concepts & Flow

How it works

There are two separate resources: Commission Rates and Commissions.

ResourceWhat it represents
BrokerCommissionRate A system-wide percentage rate (e.g. 6%) with a validity window (effective_from → effective_to). Only one rate is active at a time. Creating a new rate automatically closes the previous one.
BrokerCommission A specific commission record tied to one booking and one broker. Created automatically when a booking is confirmed. Tracks how much is owed, how much has been paid, and the current payment status.
BrokerCommissionPayment An individual cash payment against a commission (partial or full). Multiple payments can be recorded until the commission is fully paid.

Rate Statuses (derived)

Rates have no explicit status field — derive it from the dates:

ConditionDisplay as
effective_to is nullActive — currently in use
effective_to is in the pastExpired
effective_from is in the futureUpcoming

Returns the single rate whose window covers the current moment (effective_from ≤ now ≤ effective_to OR effective_to IS NULL). Use this to pre-fill or display the active rate in settings screens.

3 · Create a New Rate

POST /api/broker-commissions/rates Sets a new active rate from a given date

Creates a new commission rate. Automatically closes the currently active rate by setting its effective_to to one second before the new rate's effective_from. No manual closing needed.

🔑 manage broker commission rates

Request Body — JSON

FieldTypeRequiredDescription
percentagenumberRequiredCommission rate as a percentage. Must be > 0 and ≤ 100. Example: 6.00 means 6%.
effective_fromdatetimeRequiredWhen this rate takes effect. Format: YYYY-MM-DD HH:MM:SS. Can be future-dated.
Important: Setting effective_from in the past will immediately make this the active rate and close any overlapping previous rate. Setting it in the future creates a scheduled rate — the current rate remains active until then.

Success Response — 201 Created

{
  "message": "Broker commission rate created successfully.",
  "data": {
    "id":             3,
    "percentage":     "7.00",
    "effective_from": "2026-07-01T00:00:00.000000Z",
    "effective_to":   null,
    "created_by_user":{ "id": 1, "name": "Admin" },
    "updated_by_user":{ "id": 1, "name": "Admin" }
  }
}

Error Responses

StatusCondition
403User lacks permission
422Validation error (missing fields, percentage out of range) or unexpected server error

4 · List Commissions

GET /api/broker-commissions Paginated, filterable list

Returns all broker commissions with full related data. Ordered by eligible_at descending (most recent first). Each item includes the broker, rate, booking, unit, building, and all payments.

🔑 view broker commissions

Query Parameters

ParameterTypeRequiredDescription
broker_user_idintegerNoFilter by broker (must be a valid user ID).
statusstringNodue, partially_paid, paid, cancelled
booking_idintegerNoFilter to a specific booking's commission.
date_fromYYYY-MM-DDNoFilter commissions with eligible_at on or after this date.
date_toYYYY-MM-DDNoFilter commissions with eligible_at on or before this date.
per_pageintegerNoDefault: 15. Max: 100.
Note on date_from / date_to: These filter on eligible_at — the date the commission became payable (typically when the booking was confirmed), not the payment date.

6 · Record a Payment

POST /api/broker-commissions/{id}/payments Record a partial or full payment

Records a payment against a broker commission. Payments can be partial — record multiple until the commission is fully settled. Updates paid_amount, remaining_amount, and recalculates the commission status automatically.

🔑 record broker commission payment

Path Parameters

ParameterTypeDescription
idintegerThe broker commission ID.

Request Body — multipart/form-data

FieldTypeRequiredDescription
amountnumberRequiredAmount paid. Must be > 0.
payment_datedateRequiredDate the payment was made. Format: YYYY-MM-DD.
payment_methodstringOptionalFree text (e.g. bank_transfer, cheque, cash). Max 255 chars.
reference_numberstringOptionalTransaction or cheque reference. Max 255 chars.
receiptfileOptionalPayment receipt upload. Accepted: pdf, jpg, jpeg, png. Max 5 MB.
notesstringOptionalFree-text notes about this payment.
paid_byintegerOptionalUser ID of the person who made the payment on behalf of the company. Must exist in users table.
Overpayment: The action may enforce that amount does not exceed remaining_amount. If it throws a 422, show the error message directly to the user.

Success Response — 201 Created

    "id":               11,
    "broker_commission_id": 55,
    "amount":         "25500.00",

    "payment_method": "bank_transfer",
    "reference_number":"TRX-002",
    "receipt_path":   "brokers/commission/receipts/broker_commission_receipt_55_20260609_...",
    "notes":          null,
    "paid_by":        1,

    "id":               55,
